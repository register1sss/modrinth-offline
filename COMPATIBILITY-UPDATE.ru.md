# Обновление совместимости с Minecraft после 1.21.11

Подготовлено: 30 октября 2026 года.
База: Arian8j2/modrinth-offline, main, коммит fd19463.

## Статус

Это патч исходного кода, а не готовый установщик и не обещание отсутствия багов.
Изменения подготовлены локально. Исходный репозиторий GitHub не изменён.

Проверены метаданные Minecraft 1.21.11 (Java 21), 26.1 и 26.3 (Java 25).
Нет жёсткой таблицы новых версий: требуемая Java по-прежнему берётся из javaVersion.majorVersion в метаданных игры.
Будущие версии, изменяющие обязательный формат запуска, могут потребовать новых исправлений.

## Исправления

1. Новые метаданные 26.x содержат необязательную секцию `arguments.default-user-jvm`. Daedalus 0.2.2 не мог её десериализовать. Теперь она удаляется перед чтением типизированных данных, в том числе из кэша. Обязательные `game` и `jvm` сохранены. Настройки памяти остаются под управлением лаунчера/пользователя. Неизвестные будущие секции не игнорируются молча.
2. Правила Mojang применяются по порядку: последнее совпавшее правило определяет результат. Условия ОС и функций проверяются совместно. Не передаются неподдерживаемые Quick Play-плейсхолдеры.
3. JSON-аргумент сохраняется как один элемент argv. Пробелы в путях и значениях больше не превращаются в переносы строк и не приводят к дополнительному разбиению.
4. Classpath сохраняет порядок библиотек из метаданных и удаляет дубликаты без случайного перемешивания.
5. Архитектура правила сравнивается с архитектурой Java с учётом amd64/x86_64 и arm64/aarch64. Исправлено логическое условие для Linux ARM.
6. `test_jre` сравнивает реальную major-версию (например, 25), а не исторический префикс 1. Сохранённые Java-пути перепроверяются. Неверная пользовательская Java даёт понятную ошибку; удаление пользовательского пути возвращает автоматический выбор. После скачивания Java проверяется её работоспособность и версия. Добавлены варианты расположения Java в macOS-архивах; на macOS это не проверялось.
7. Сценарии GitHub Actions переведены с ubuntu-20.04 на ubuntu-22.04. В сценарии сборки приложения обновлены устаревшие checkout/cache/setup-node/upload-artifact и добавлен запуск тестов библиотеки перед сборкой. Эти сценарии в GitHub здесь не запускались.

## Результаты тестов

Среда: Linux x86_64, Rust 1.99.1, Corretto OpenJDK 25.0.4.1.

- `cargo test -p theseus --lib --locked`: 16 прошли, 0 ошибок, 2 opt-in теста пропущены.
- Отдельный запуск opt-in тестов с настоящей Java 25: 2 прошли, 0 ошибок.
- Реальная Java 25 корректно определяется; проверка другой major-версии возвращает false.
- JVM-флаги из метаданных 26.1 и 26.3 принимаются Java 25 при запуске с `-version`.
- Проверены чтение метаданных, подстановка JVM/game-аргументов, пути с пробелами, отсутствие неразрешённых плейсхолдеров, порядок classpath, правила и архитектуры.
- Форматирование изменённых Rust-файлов и `git diff --check` прошли.
- При компиляции остаются пять существующих предупреждений dead_code для event payload-структур.

Команды для повторения:

```sh
cargo test -p theseus --lib --locked
```

Дополнительно, для Linux с Java 25 в /usr/bin/java:

```sh
TEST_JAVA_PATH=/usr/bin/java TEST_JAVA_MAJOR=25 cargo test -p theseus --lib --locked -- --ignored
```

Переменная TEST_JAVA_PATH должна указывать на исполняемый файл, а не каталог.

## Применение

### Архив исходников

Распакуйте архив в отдельную папку. В нём уже применены изменения. Не подменяйте им папку установленного приложения.

### Отдельный патч

В чистой копии исходного проекта на указанном базовом коммите:

```sh
git apply --check /path/to/modrinth-offline-modern-minecraft.patch
git apply /path/to/modrinth-offline-modern-minecraft.patch
cargo test -p theseus --lib --locked
```

Перед обновлением установленного приложения сделайте резервную копию игровых профилей и миров.

## Сборка приложения

Нужны Rust stable, Node.js 20 и pnpm 9.4.0, а также системные зависимости Tauri 1.
На Windows дополнительно нужны Visual Studio C++ Build Tools и WebView2.
На Ubuntu 22.04 системные пакеты перечислены в `.github/workflows/app-release.yml`.

Из корня проекта:

```sh
pnpm install --frozen-lockfile
pnpm app:build
```

Установочные пакеты Tauri обычно находятся в `target/release/bundle/`.
Альтернатива: загрузить изменения в собственный fork GitHub и вручную запустить workflow «Modrinth App build» во вкладке Actions. При успешной сборке установщики будут в артефактах соответствующей ОС.

Если в профиле вручную указан путь к Java 17/21, удалите этот путь перед установкой Minecraft 26.x, чтобы лаунчер выбрал Java из метаданных, или укажите Java 25 самостоятельно. При проблемах существующего профиля используйте восстановление/переустановку его файлов после резервного копирования миров.

## Что не проверено

- Полная сборка Tauri/frontend и создание установщика.
- Реальный запуск Minecraft до главного меню и загрузка мира.
- Автоматическое скачивание и установка Java через UI.
- Windows, macOS, ARM, специфические GPU и драйверы.
- Fabric, Forge, NeoForge, отдельные моды и модпаки, сетевые серверы.
- Снапшоты и версии после 26.3.

Совместимость лаунчера не делает старые моды совместимыми с новой игрой.
Офлайн-профиль не даёт доступ к серверам, требующим официальной проверки аккаунта.
Для полноценной приёмки нужны тесты на целевой ОС: чистый vanilla-профиль каждой версии, запуск с Java из метаданных, вход в мир, повторный запуск и затем отдельные тесты нужных загрузчиков/модов.
