# U3drinth: диагностика экземпляров, первая реализация

База: `eda7a8d89b6a6e58b1887121745c3da79204b6fd`.
Изменения находятся в исходниках. Windows-установщик собирается в GitHub Actions (workflow «U3drinth Windows installer»).

## Что добавлено

### Вылеты и восстановление
- Для новых процессов сохраняется настоящий код выхода дочернего процесса. Спящий процесс больше не считается завершившимся.
- Порядок событий: сначала запуск, затем завершение, даже при быстром вылете.
- Обычный выход с кодом 0 и остановка кнопкой лаунчера не вызывают предложение починки.
- Локальный анализ свежего `logs/latest.log`: память, Java, зависимости, Mixin, повреждённые файлы, сохранение crash report.
- Логи не отправляются в облако. Общая строка ERROR сама по себе не считается вылетом.
- При неизвестной причине предлагается диагностика, без обещания универсальной починки.
- По подтверждению восстанавливаются скачанные файлы игры и загрузчика через существующий установщик.
- Перед восстановлением сохраняются метаданные профиля и options в `u3-repair-backups/<uuid>/`.
- Моды, config и миры не изменяются кодом диагностики. Общие скачанные библиотеки заново загружаются, а не резервируются.
- Ошибка восстановления не оставляет экземпляр навечно в состоянии Installing. Параллельная починка блокируется, работающий экземпляр чинить нельзя.
- После перезапуска лаунчера у подхваченных процессов нет настоящего exit status; для них не показывается непроверенный старый вылет.

### Дерево зависимостей и удаление
- Читаются Fabric, Quilt, Forge и NeoForge манифесты, включая предоставляемые идентификаторы.
- Вкладка «Диагностика» содержит раскрываемое дерево с защитой от циклов.
- Удаление одного мода, выбранных файлов и отключённых файлов проходит через просмотр последствий.
- Показываются прямые и транзитивные обязательные зависимости, отдельно необязательные функции.
- Несколько поставщиков одного идентификатора учитываются. Отключённые файлы не считаются активными поставщиками.
- Можно явно выбрать удаление затронутых зависимых модов. По умолчанию это выключено.
- Перед удалением повторно читается состав модов; если он изменился, требуется новое подтверждение.
- Неизвестные манифесты и вложенные JAR помечаются как неполные сведения. Ограничения версий отображаются, но не разрешаются как полноценным загрузчиком.

### Ресурсы
- Показываются RAM и CPU зарегистрированного процесса игры с проверкой PID и времени запуска.
- CPU 100% = одно логическое ядро; это расход процесса JVM, не каждого мода.
- Ручной замер усредняет три пробы. Хранятся последние 10 замеров экземпляра в текущем сеансе, в том числе при переходах между вкладками.
- Можно сравнить базовый и последний замер: изменение RAM/CPU и добавленные, удалённые, включённые или изменённые файлы.
- Для проверки влияния мода нужно менять один мод и повторять тот же сценарий игры. Это корреляция, а не доказательство причинности.
- Точный рейтинг расхода RAM/CPU по каждому моду НЕ реализован. Для него нужен профилировщик внутри JVM и более глубокая интеграция.

### Проверка файлов
- Кнопки проверки всех модов и отдельного файла.
- Локальная статическая проверка JAR: SHA-256, читаемость, подозрительные пути, вложенные скрипты/исполняемые файлы, отдельные сочетания строк в bytecode.
- Лимиты: 256 МиБ на файл, 20 000 ZIP-записей, 1 МиБ на манифест, 32 МиБ анализируемого bytecode. Неполная проверка явно обозначается.
- Моды не исполняются и архивы не извлекаются. Симлинки, junction и выход из каталога экземпляра запрещаются.
- На Windows файл можно проверить Microsoft Defender (`MpCmdRun -Scan -ScanType 3 -File ... -DisableRemediation`). Лаунчер сам не удаляет файлы; действуют системные политики антивируса.
- Код 2 у Defender не объявляется доказанным вирусом: он может означать находку или ошибку сканирования. Пользователю предлагается проверить журнал защиты Windows и рассмотреть отключение мода.
- На других ОС или без доступного Defender выводится «проверка недоступна», а не «безопасно».
- Лаунчер не загружает файлы на сторонние сервисы. Сам Defender может использовать облачную защиту согласно настройкам Windows.
- Статические признаки не доказывают заражение, отсутствие находок не гарантирует безопасность.

## Обновление: понятная диагностика

### Что исправить
- Вверху вкладки «Диагностика» короткий итог («Найдено N проблем: игра может не запуститься») и четыре счётчика: включённые моды, моды, нужные другим модам, проблемы, мешающие запуску, и то, что стоит проверить.
- Каждая проблема описана человеческим языком: что случилось, какой мод этого требует, какая версия нужна, и отдельной строкой «Как исправить». Под карточкой ссылки на затронутые моды открывают их в дереве.
- Распознаются: отсутствующая обязательная зависимость, отключённая зависимость, неподходящая версия зависимости, мод под другой загрузчик (Forge/NeoForge/Fabric/Quilt), мод под другую версию Minecraft, слишком старый загрузчик, один мод в нескольких копиях, объявленные несовместимости, нераспознанные файлы и подозрительные признаки.
- Диапазоны версий Fabric, Quilt и Forge/NeoForge (Maven) переводятся в понятный вид: «не ниже 0.95.0», «только 1.20.1», «от 1.20 до 1.21».

### Дерево зависимостей
- Для каждого мода видно три группы: «Требует» (что нужно для запуска, с нужной и установленной версией), «Может работать вместе с» (необязательные), «Нужен для» (какие моды перестанут работать без него).
- Зависимости раскрываются вложенно, циклы обрываются. Minecraft, Java и загрузчик показаны отдельными строками с версией профиля.
- Учитываются моды, встроенные внутрь других JAR (Jar-in-Jar): такие зависимости считаются установленными и подписываются, в каком файле они лежат.
- Поиск по названию, ID и имени файла, фильтры «Все», «С проблемами», «Библиотеки», «Отключённые». Для частых библиотек показываются понятные названия, даже если они не установлены.

### Окно вылета и удаление
- Окно вылета называет профиль, вероятную причину, совет и строки лога, на которых основан вывод. Кнопки: «Закрыть», «Открыть диагностику», «Восстановить файлы».
- Диалог удаления перечисляет моды, которые перестанут запускаться («нужен «Fabric API»»), необязательные связи и неполные сведения. Подтверждение требуется только если удаление что-то ломает.

### Список содержимого
- Для файлов, скачанных не через каталог, показываются название и версия из манифеста мода, а имя файла второй строкой. Поиск учитывает имя файла, сортировка по названию не зависит от регистра.

## Область поддержки

Это инструменты обычных Minecraft-экземпляров. Нативные моды Horizon и механики самого Horizon данной диагностикой не анализируются. Это не исправление всех игровых багов Horizon.

## Проверки

```sh
pnpm install --frozen-lockfile
pnpm --filter @modrinth/app-frontend run build
node --test apps/app-frontend/tests/*.test.mjs
SQLX_OFFLINE=true cargo check -p theseus --lib
SQLX_OFFLINE=true cargo test -p theseus --lib instance_health::tests
SQLX_OFFLINE=true cargo test -p theseus --lib health_process_tests
```

Проверены локально: сборка frontend, компиляция библиотеки Rust на Linux, JS-тесты зависимостей/сравнения/фильтрации выходов, Rust-тесты манифестов, ограничений, симлинков, ZIP traversal и состояния процессов. Кнопки, дерево, замер и окно вылета дополнительно проверены в Chromium с тестовыми данными, не с работающим Minecraft.

Нужно проверить на Windows перед релизом: Tauri IPC, фактический запуск Minecraft и вылет, восстановление с отключённой сетью, Defender (включён/отключён), реальную нагрузку игры и установщик. Windows-сборка и проверка Defender на Windows здесь не выполнялись.
